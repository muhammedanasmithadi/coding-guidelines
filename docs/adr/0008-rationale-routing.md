# ADR 0008: Rationale routing and ADR integrity

- Status: accepted
- Context: `docs/01-principles.md` banned comments and sent surviving rationale to ADRs, but the rule was stated three ways (`docs/01-principles.md`, `docs/31-classic-principles.md`, `docs/20-docs-as-code.md`), enforced unevenly (`scripts/check_tree.py` flags Python `#` comments and `//` in JS/TS/shell/config; it passes Python docstrings, TypeScript block comments, and every Rust/Kotlin/C/Go comment), and the ADR set had no supersede chain (ADR-0003 defers Rust and C, ADR-0005 adds them, both `accepted`). Six of seven records omitted the `Options` field the template requires, so the one part that makes an ADR worth more than a commit message went unwritten. No record linked to the code it governed, so ADRs were findable by decision and never by code site.
- Options: (A) keep ADRs as the catch-all for any rationale that would have been a comment; (B) route each kind of rationale to the container that holds it (code, rule doc, ADR), state one canonical comment clause, and enforce each container separately; (C) keep comments and standardize them instead of banning them.
- Decision: (B). One canonical clause in `docs/01-principles.md`: no comments in code; add one only when absolutely required, and only because a named tool or external contract forces it. Rationale about an approach lives in an ADR; rationale about a line lives in the code (names, types, structure, tests). ADRs gain a `Supersedes` field, a required field set (`Status`, `Context`, `Options`, `Decision`, `Consequences`), and a link convention: the ADR ID lives in a name or a `rationale:` config field, never in a comment. The bar for writing one is two real alternatives and high reversal cost; MAJOR gate changes, breaking APIs, and topology choices are sufficient conditions. A decision that a machine can check gets an enforcing artifact carrying its ID; one it cannot states `Enforcement: review`.
- Consequences: `scripts/check_tree.py` gains ADR-field, ADR-link, docstring, block-comment, and language-config checks; 30 module docstrings leave the tree and their content moves to a script index in `docs/tooling.md`; Go keeps godoc because `docs/languages/go.md` requires it; the ADR set gains a supersede chain, so ADR-0003 is superseded by ADR-0005. ADRs 0002 to 0007 were backfilled with the `Options` field this record requires; their context, decision, and consequences are unchanged, and this backfill is the one permitted edit to an accepted record. Every record also states `Enforcement`, which makes the gate-backed decisions checkable: ADR-0002 by `check_health_endpoints`, ADR-0005 by `check_language_configs` and `check_enforce_refs`, ADR-0006 and ADR-0007 by `check_runtime_baseline` against `runtime-baseline.yml`. The new gates ratchet: `waivers/baseline.check-tree.json` holds the findings an adopting repo accepts today, so a legacy repo adopts the gate without failing CI on day one, while a new finding still blocks.
- Enforcement: `scripts/check_tree.py` (blocking); `scripts/check-comments.sh` (advisory, Rust/Kotlin/C/Go).
